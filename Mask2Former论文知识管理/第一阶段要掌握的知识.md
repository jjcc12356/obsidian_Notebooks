## 张量形态：
==**看到任意张量形态时，能够立刻说出每个数字代表什么，并判断它能不能送进Mask2Former**==
### python知识
- `变量.shape`：查看形状
- `变量.ndim`：查看维度数量
- Python下标从 `0` 开始
### 张量 Tensor
装着大量数字的多维容器
不同维度可以这样理解：

|类型|示例|维度数|
|---|---|---|
|一个数字|`5`|0维|
|一排数字|`[1, 2, 3]`|1维|
|一张数字表|`[[1,2],[3,4]]`|2维|
|一张多通道影像|`[C,H,W]`|3维|
|一批多通道影像|`[B,C,H,W]`|4维|
深度学习中的影像并不是以“图片”的形式进入模型，而是先转换成由像元数值组成的张量。
### 什么是张量形状
假设：

```
image.shape
```

输出：

```
torch.Size([4, 5, 512, 512])
```

这个张量有4个维度：

```
[4, 5, 512, 512]
 │  │    │    │
 B  C    H    W
```
含义如下：

|字母|含义|当前数值|
|---|---|---|
|`B`|Batch，一批有多少张影像|4|
|`C`|Channel，每张影像有多少个通道|5|
|`H`|Height，影像高度|512|
|`W`|Width，影像宽度|512|
所以：

```
[4, 5, 512, 512]
```

表示：

> 一批有4张影像；每张影像有5个通道；每个通道大小为512×512像元。

在项目中，这5个通道可能依次是：

```
0：R
1：G
2：B
3：NDRE
4：DSM
```
### 单张影像为什么没有B

单张五通道影像通常是：

```
[5, 512, 512]
```

也就是：

```
[C, H, W]
```

将多张影像交给 DataLoader 组成一个批次后，才会增加最前面的批次维度：

```
单张影像：[C, H, W]
                     ┐
单张影像：[C, H, W]  │
单张影像：[C, H, W]  ├──→ [B, C, H, W]
单张影像：[C, H, W]  │
                     ┘
```

例如：

```
单张：[5, 512, 512]
4张：[4, 5, 512, 512]
```

注意：==**`B=4`并不代表数据集只有4张影像，只表示模型这一次同时处理4张。**==
### 三通道与五通道有什么区别

原始RGB输入：

```
[B, 3, H, W]
```

改为多模态输入：

```
[B, 5, H, W]
```

例如：

```
# RGB
[4, 3, 512, 512]

# RGB + NDRE + DSM
[4, 5, 512, 512]
```

真正发生改变的是：

```
C：3 → 5
```

因此，模型第一层原来如果只接收3通道：

```
in_channels = 3
```

现在输入五通道张量，就会发生不匹配：

```
模型期待：[B, 3, H, W]
实际输入：[B, 5, H, W]
```

常见报错会类似：

```
expected input to have 3 channels, but got 5 channels
```

把第一层改成5只能说明“模型可以接收五通道”，不等于“模型已经学会有效利用NDRE和DSM”。这正是当前论文问题的核心。
### 怎样取出不同部分

假设：

```
x.shape == [4, 5, 512, 512]
```

### 1. 取第一张影像

```
x[0]
```

结果形状：

```
[5, 512, 512]
```

因为选定了一张影像，`B`维度消失了。

### 2. 取所有影像的RGB通道

```
x[:, 0:3, :, :]
```

结果形状：

```
[4, 3, 512, 512]
```

也可以简写成：

```
x[:, :3]
```

### 3. 取所有影像的NDRE

如果NDRE是第4个通道：

```
x[:, 3:4, :, :]
```

结果形状：

```
[4, 1, 512, 512]
```

这里用 `3:4`，而不直接使用 `3`，是为了保留通道维度。

对比：

```
x[:, 3].shape
# [4, 512, 512]

x[:, 3:4].shape
# [4, 1, 512, 512]
```

在卷积神经网络中，通常需要保留 `C` 这个维度，所以第二种更安全。
###  一个特别容易踩的坑

PyTorch模型通常使用：

```
[B, C, H, W]
```

但有些图像数据可能使用：

```
[B, H, W, C]
```

例如看到：

```
[4, 512, 512, 5]
```

这表示通道在最后，不能直接按一般PyTorch卷积的格式使用。

需要改变维度顺序：

```
x = x.permute(0, 3, 1, 2)
```

变化过程：

```
[4, 512, 512, 5]
       ↓
[4, 5, 512, 512]
```

现在先记住：

> PyTorch图像模型通常要求通道 `C` 位于第二个位置。
![[Pasted image 20260923105622.png]]
RGB   = [3, H, W]
NDRE  = [1, H, W]
DSM   = [1, H, W]
合并后 = [5, H, W]
批处理 = [B, 5, H, W]

如果使用PyTorch拼接，通常是在通道维拼接：

```
image = torch.cat([rgb, ndre, dsm], dim=0)
```

单张影像的 `dim=0` 是通道维。

如果已经有批次：

```
images = torch.cat([rgb, ndre, dsm], dim=1)
```

批次张量的 `dim=1` 才是通道维。

这是非常关键的区别：

|张量|形状|通道所在维度|
|---|---|---|
|单张影像|`[C,H,W]`|`dim=0`|
|一批影像|`[B,C,H,W]`|`dim=1`|

### 一、切片规则

基本形式：

```
x[start:stop]
```

需要注意：

> 包含 `start`，不包含 `stop`。

例如通道编号是：

```
0：R
1：G
2：B
3：NDRE
4：DSM
```

那么：

```
x[:, 0:3]
```

会取得通道：

```
0、1、2
```

也就是RGB，不包括编号3。

因此：

```
rgb  = x[:, 0:3]  # 也可以写成 x[:, :3]
ndre = x[:, 3:4]
dsm  = x[:, 4:5]
```

假设：

```
x.shape = [4, 5, 512, 512]
```

则：

```
rgb  → [4,3,512,512]
ndre → [4,1,512,512]
dsm  → [4,1,512,512]
```

---

### 二、使用 `torch.cat()`拼接通道

假设已有：

```
rgb.shape  == [4, 3, 512, 512]
ndre.shape == [4, 1, 512, 512]
dsm.shape  == [4, 1, 512, 512]
```

要把它们组成五通道输入：

```
x = torch.cat([rgb, ndre, dsm], dim=1)
```

结果：

```
x.shape == [4, 5, 512, 512]
```

为什么是 `dim=1`？

```
dim=0 → B，批次维
dim=1 → C，通道维
dim=2 → H，高度维
dim=3 → W，宽度维
```

我们要增加通道数量，所以沿 `dim=1` 拼接。

拼接过程：

```
[B,3,H,W]
[B,1,H,W]  --沿dim=1拼接--> [B,5,H,W]
[B,1,H,W]
```

`torch.cat()`是在已有维度上连接，不会凭空增加新的维度。

---

### 三、为什么有时需要 `unsqueeze()`

实际读取NDRE时，可能得到：

```
ndre.shape == [4, 512, 512]
```

它只有：

```
[B,H,W]
```

缺少通道维度 `C`，不能直接与：

```
rgb.shape == [4,3,512,512]
```

进行通道拼接。

需要在 `dim=1` 增加一个维度：

```
ndre = ndre.unsqueeze(1)
```

变化为：

```
原来：[4,512,512]
现在：[4,1,512,512]
```

DSM同理：

```
dsm = dsm.unsqueeze(1)
```

之后才能拼接：

```
x = torch.cat([rgb, ndre, dsm], dim=1)
```

得到：

```
[4,5,512,512]
```

---

### 四、单张影像与批次的区别

如果处理的是单张影像：

```
RGB ：[3,H,W]
NDRE：[1,H,W]
DSM ：[1,H,W]
```

通道维是 `dim=0`：

```
image = torch.cat([rgb, ndre, dsm], dim=0)
```

结果：

```
[5,H,W]
```

如果处理的是一批影像：

```
RGB ：[B,3,H,W]
NDRE：[B,1,H,W]
DSM ：[B,1,H,W]
```

通道维是 `dim=1`：

```
images = torch.cat([rgb, ndre, dsm], dim=1)
```

结果：

```
[B,5,H,W]
```

必须记住：

|数据状态|形状|通道维|拼接参数|
|---|---|---|---|
|单张影像|`[C,H,W]`|`dim=0`|`dim=0`|
|一批影像|`[B,C,H,W]`|`dim=1`|`dim=1`|
完成拼接后，不能只看有没有报错，至少要检查：

```
print(rgb.shape)
print(ndre.shape)
print(dsm.shape)
print(x.shape)
```

理想输出类似：

```
RGB:   [4,3,512,512]
NDRE:  [4,1,512,512]
DSM:   [4,1,512,512]
Input: [4,5,512,512]
```

如果得到：

```
[4,512,512,5]
```

说明通道位置不对。

如果得到：

```
[12,1,512,512]
```

说明很可能把批次维与通道维混淆了。

## `dtype`是什么

`dtype`表示张量中数字的数据类型：

```
print(x.dtype)
```

常见结果：

|dtype|含义|是否常用于模型输入|
|---|---|---|
|`torch.uint8`|0～255整数影像|不能直接训练|
|`torch.int64`|整数，常用于类别标签|通常不用作影像输入|
|`torch.float32`|单精度浮点数|最常用|
|`torch.float16`|半精度浮点数|常用于混合精度训练|

深度学习影像输入通常应为：

```
torch.float32
```

转换方式：

```
x = x.float()
```

但要注意：

```
x = x.float()
```

只改变数据类型，不改变数值范围。

例如：

```
uint8：255
转换后
float32：255.0
```

它不会自动变成 `1.0`。

如果RGB原来为0～255，常见处理是：

```
rgb = rgb.float() / 255.0
```

变化为：

```
0～255 → 0～1
```
## 检查数值范围

最基本的检查：

```
print(x.min())
print(x.max())
print(x.mean())
print(x.std())
```

分别表示：

- `min`：最小值
- `max`：最大值
- `mean`：平均值
- `std`：标准差，反映数据波动程度

但是对于你的五通道数据，不能只检查整个张量，因为不同模态的数值范围不同。

应该分别检查：

```
rgb = x[:, :3]
ndre = x[:, 3:4]
dsm = x[:, 4:5]
```

然后分别查看：

```
print(rgb.min(), rgb.max())
print(ndre.min(), ndre.max())
print(dsm.min(), dsm.max())
```

可能得到：

```
RGB：  0～1
NDRE：-0.8～0.9
DSM：  0～35
```

虽然形状完全正确，但三种模态的数值尺度明显不同。

如果不处理，DSM数值可能远大于RGB和NDRE，影响模型优化。这并不能直接证明模型一定忽略辅助模态，但它是必须排查的风险。
## NaN、Inf和NoData

### 1. NaN

NaN表示“不是一个有效数字”：

```
torch.isnan(x).sum()
```

结果如果是：

```
tensor(0)
```

表示没有NaN。

如果大于0，说明数据中存在异常值。

### 2. Inf

Inf表示正无穷或负无穷：

```
torch.isinf(x).sum()
```

模型输入中通常不能存在Inf。

也可以一次性检查是否都是有限数字：

```
torch.isfinite(x).all()
```

如果结果为：

```
tensor(True)
```

说明没有NaN和Inf。

### 3. NoData

NoData最危险，因为它不一定是NaN。

遥感数据中可能用下面的数值表示无数据：

```
-9999
-32768
65535
```

例如DSM统计结果为：

```
min = -9999
max = 35
```

`torch.isnan()`可能仍然返回0，因为 `-9999` 是一个普通数字，只是它在数据语义上表示无效像元。

如果直接输入模型，`-9999` 会成为极端异常值。
假设五通道输入是：

```
RGB：   0～1
NDRE： -1～1
DSM：-9999～35
```

形状上：

```
[B,5,H,W]
```

完全正确。

但数值上，DSM中的 `-9999` 会严重干扰：

- 卷积结果；
- 梯度大小；
- 特征分布；
- 模型对DSM通道的判断；
- 后续归一化。

因此“五通道AP下降”可能不是融合架构本身造成的，而是输入数据质量问题。
# 归一化的基本思想

归一化不是单纯“把数值变小”，而是让不同通道进入适合模型学习的数值尺度。

标准化常见公式：

x′=x−μσx'=\frac{x-\mu}{\sigma}

其中：

- xx：原始像元值
- μ\mu：训练集平均值
- σ\sigma：训练集标准差
- x′x'：标准化结果

结果通常接近：

```
均值约为0
标准差约为1
```

你的数据一般需要分别处理：

```
RGB  → 保持与预训练模型一致的归一化
NDRE → 使用NDRE训练集统计量
DSM  → 使用DSM训练集统计量
```

不能把五个通道混在一起计算一个总平均值。

也不建议每张小图单独计算DSM均值和标准差，因为这样可能破坏DSM的绝对高度信息。更稳妥的是使用训练集统计量，并把同一套统计量应用于验证集和测试集。
